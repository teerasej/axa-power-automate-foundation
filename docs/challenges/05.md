# Challenge 5 — Teams service-request routing

![A service coordinator moves an incoming message to a separate receiving-team queue.](/images/challenge-05-teams-service-routing.png)

## Scenario

The Service Intake Teams channel receives internal service requests. Normal messages go to a separate Service Queue channel. Messages beginning with [URGENT] should alert the on-duty role.

Use fictional information only. These are training examples, not organisational policies. This challenge is a physical-card simulation; no software account or paid licence is required.

## Goal

Forward a normal new top-level message to Service Queue without posting back to Service Intake.

## What you need

Supplied Flow cards, post-its and your group. Use only available cards; notes may explain repeated uses, roles or inputs.

## Normal test case

Source: Service Intake. Message: Please review the new internal request. Destination: Service Queue, a different channel.

## Steps

1. Identify the new-message event and its source channel.
2. Show the normal message reaching the separate destination.
3. Make the source and destination visible beside the cards.
4. Walk the normal case and request a basic-sequence check.

## Check your result

The normal message reaches the separate Service Queue channel. Posting back into the monitored intake channel is not an acceptable normal outcome.

An instructor/TA awards one point for an accepted basic sequence, only once for this challenge. Detailed configuration and a complete exception route are not required. Hints and retries are allowed without deductions.

::: details Optional exception discussion

How would [URGENT] Service interruption reported. reach the duty role by email? Discuss why a Reply to an existing post does not start this particular Trigger.


:::
