# Challenge 5 — Teams service-request routing

![A service coordinator moves an incoming message into a separate team queue.](/images/challenge-05-teams-service-routing.png)

## Scenario

The team uses the `Service Intake` channel to receive internal service requests. A message that begins with `[URGENT]` must notify the on-duty role by email. A normal message must be forwarded to the `Service Queue` channel.

Do not use real messages or user information during testing.

<span id="your-challenge"></span>
<span id="arrange-and-explain"></span>

## Challenge

Arrange the Flow cards to check a new top-level channel message and branch according to the `[URGENT]` tag without creating a loop that triggers the workflow again.

> **Boundary:** Use only the node cards in the physical deck. Do not add an Action for creating a ticket, assigning a person, or editing a message because those cards are not available.

> **For this game:** The complete workflow includes both outcomes. Build and explain the normal path under **Required for 1 point** first. The other outcome is optional and earns no extra points.

<span id="try-the-normal-case"></span>
<span id="check-your-result"></span>

## Checkpoint

**Required for 1 point:** Show a new, normal top-level message moving from `Service Intake` to the separate `Service Queue` channel. The destination must not be the channel monitored by the Trigger, so posting the message does not start the flow again.

Explain your valid starting Trigger, connected supplied cards and normal result to the instructor/TA. Only the instructor/TA records the accepted point.

**Optional discussion:** Walk through a message beginning with `[URGENT]` and show how the on-duty role receives an email. Explain that the deck's `When a new channel message is added` Trigger responds to new top-level posts, not Replies to existing posts. Keep every destination outside the monitored channel.

You can earn the point without completing the optional discussion or recalling a technical limitation.
