# Challenge 3 — Field-support request routing

![A field colleague submits a support form as an office team receives the details.](/images/challenge-03-field-support-routing.png)

## Scenario

A field team submits support requests through a form with a subject, contact email, urgency and description. The receiving team needs the response details before it can act.

Use fictional information only. These are training examples, not organisational policies. This challenge is a physical-card simulation; no software account or paid licence is required.

## Goal

Retrieve a complete response and notify the receiving team in Microsoft Teams.

## What you need

Supplied Flow cards, post-its and your group. Use only available cards; notes may explain repeated uses, roles or inputs.

## Normal test case

Subject: Partner event support. Contact email: provided as a fictional value. Urgency: Normal. Description: complete. The receiving team sees the request details.

## Steps

1. Identify the form-submission event.
2. Show how the submitted response is identified and its details retrieved.
3. Use the retrieved details in the receiving-team notification.
4. Walk the complete-response case and request a basic-sequence check.

## Check your result

The response details are retrieved before they are used in the notification; a Response Id alone is not the answers.

An instructor/TA awards one point for an accepted basic sequence, only once for this challenge. Detailed configuration and a complete exception route are not required. Hints and retries are allowed without deductions.

::: details Optional exception discussion

What should happen when Description is blank? Discuss the completeness rule and an email asking for missing details.


:::
